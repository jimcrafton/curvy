Pen path drawing and editing

Working test bench for the bezier path interaction that the bezierPath node will need. Everything runs on pointer events, so a pen shows hover badges before it touches the surface and reports pressure; the mouse works too (right button stands in for the barrel button). Try it: draw with the pen tool, edit the sample shapes with the direct tool, scribble with freehand and then hold F to re-fit.

How it works (proposal)

  • Pen tool (P). Click = corner point, drag = smooth point (the drag pulls the outgoing handle, the incoming one mirrors it). Hover the first point of an open path to close it, the last point to continue it. With a path already there, the same tool adds a point on a segment and deletes a point, so you rarely switch tools. A badge at the tip names what a touch will do, which a hovering pen can show before it lands. A dashed rubber band previews the next segment.
  • Keyboard hand while placing a point: hold Shift to constrain to 45 degrees, hold Alt to break the handle (a cusp point), hold Space to move the anchor instead of pulling its handle. Enter or Esc finishes an open path (a double touch does too), Backspace removes the last point.
  • Direct tool (A). Drag a point or a handle; drag a segment to bend it (the curve follows the pen, the handles adapt); drag on empty canvas to marquee-select points; double-tap a point to flip corner/smooth. Smooth points keep their handles collinear, symmetric points keep them equal too, and Alt-dragging a handle turns the point into a corner.
  • Point ring (barrel button, or tap Space over a point): Smooth S, Corner C, Symmetric Y, Delete, Add (midpoint after), Cut, Close, Reverse. The eraser end of the pen deletes the point it touches.
  • Freehand (B) keeps the raw samples and fits curves through them (corner angle decides where it breaks). Hold F and move the pen vertically to re-fit: up simplifies, down follows the stroke more closely, and the point count is live in the fixed card. Release to keep it (one undo step). Editing the anchors needs a bake first (a button on the fitCurve box), which drops the raw samples.
  • fitCurve node: a fresh freehand stroke is a fitCurve node feeding the bezierPath. Its Smooth and Corner sliders in the HUD are the node's parameters (the header sliders only set the defaults for new strokes), and the F scrub drags the Smooth one. The HUD shows them whenever the path still has its samples.
  • Pressure and tilt (pen only): freehand records pressure and tilt with every sample. The fitCurve node averages them into a pressure and a tilt attribute on each anchor; it does not decide a width. The Stroke node maps pressure to width (Min/Max width, a Response curve drawn as a small plot, Width smooth), and the header sliders only set its defaults for new strokes. In the pen tool the pressure while you place a point (the peak while you drag) is stored as that point's pressure. Hold W over a point and move up/down to set an explicit width override on it; the HUD shows it and a button returns it to the pressure-driven width. Pressure and tilt survive Bake, so the response can still be changed afterwards. A mouse gives an even width and no tilt.
  • Nib preview: a hovering or touching pen shows a nib at its tip: size follows pressure (dashed minimum size while hovering), the ellipse stretches and turns with the lean, and a tail shows where the pen body points. Anchors that recorded a tilt show a small dashed nib, and a selected anchor shows its width as an amber tick. Tilt is only shown here; it will drive calligraphic and star brush angles in the Brushes tab, and it does not change the path.
  • Context HUD (top right) appears with a selection: X/Y, the point type, handle lengths, and the path size. The grey chip next to the path is the graph view's peek of the same object.

What this means for the graph and the code

  • A path is one bezierPath node whose parameters are the anchors: position, in/out handle (relative), and a type tag (corner, smooth, symmetric), plus a closed flag. The type tag is stored so smooth points stay smooth when edited; the curve itself is just anchors and handles.
  • One drag, one undo step: every interaction here takes a snapshot on touch-down and pushes it on release only if something changed, which is how the shared UndoStack closures should work.
  • Freehand stores its samples next to the node while it is fresh (as the node's input), so the fit can be re-run with a different tolerance. Editing points is blocked with a hint until the user bakes the stroke (a button on the fitCurve box); baking drops the samples and the anchors become the source of truth.
  • Cutting an open path in the middle splits the node into two bezierPath nodes; joining two end points merges two nodes. The sample implements the first (Cut) but not joins across paths.

Not in this mockup

  • Downstream attribute nodes (taper, noise, remapping pressure), the curvature pen (drawing without handles), pan and zoom (Space drag and the wheel), snapping to other paths, and joining two open paths by their ends.
